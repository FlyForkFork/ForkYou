# 08 收获：10 个能搬走的想法，和 7 张面试卡

> 这篇回答什么问题：这个项目有哪些设计值得抄？哪些是坑？面试聊它时怎么讲清楚？

## 可迁移的 10 个想法

### 1）先备镜像，再删旧容器

- **问题**：有状态服务升级时，拉取失败会怎样？
- **做法**：`ensureImage()` 成功后才删旧容器（`panel/server/src/docker.ts:749-763`）。
- **为什么好**：失败时旧服务仍在，不会「升级升没了」。
- **怎么用**：任何 `docker compose up` 之前先 `docker pull`；K8s 用 maxUnavailable=0 同理。

### 2）恢复操作永远不换版本

- **问题**：看门狗重启时本地 `:latest` 刚好被更新，实例会不会悄悄换镜像？
- **做法**：所有自愈/重启走 `runInstance(inst, { keepImage: true })`，只有显式升级才换（`panel/server/src/docker.ts:749-753`；`panel/server/src/index.ts:1767`）。
- **为什么好**：用户没点升级，系统就不能升级——避免「我什么都没动它怎么坏了」。
- **怎么用**：把「重建」和「升级」拆成两个 API，恢复路径只读当前版本。

### 3）单写者 lease + viewer 标识

- **问题**：远程桌面允许多个页面同时连，会泄漏/卡死。
- **做法**：每个页面一个 viewer id，新页面接管时旧页面标记 superseded 并断 socket；被接管页面自动重连直接 409（`panel/server/src/index.ts:1085-1141`、`panel/server/src/index.ts:2000-2013`）。
- **为什么好**：既保证单连接，又不会两边互踢。
- **怎么用**：任何「同一资源只能一个活动编辑者」的场景（协同编辑器、远程终端）。

### 4）用真实请求判活，别用健康检查猜

- **问题**：KasmVNC 卡死时静态页照常 200，HTTP 探针永远绿。
- **做法**：盯真实用户请求，25 秒无任何响应才算一次 hang；快速失败不计数（`panel/server/src/index.ts:1738-1773`）。
- **为什么好**：信号来自用户实际路径，不受预热期/后台标签页影响。
- **怎么用**：反代层加「上游无响应」计时器，而不是另起一套探测。

### 5）声明式重建，绝不克隆旧容器

- **问题**：`docker inspect` 旧容器再克隆，会把过期 Hostname/IP 带过来。
- **做法**：所有 create 参数写死在 `runInstanceNow`（`panel/server/src/docker.ts:775-821`）。
- **为什么好**：重建结果可预测，不会被运行时衍生值污染。
- **怎么用**：IaC 思维——容器是 cattle，不是 pet。

### 6）错误分阶段 + 人话建议

- **问题**：Docker 原始错误用户看不懂。
- **做法**：`ProvisionError` 分 pull/volume/create/start 四阶段，映射「没空间/被限流/manifest 不存在」等建议（`panel/server/src/docker.ts:573-629`）。
- **为什么好**：支持成本大幅下降，用户能自己修。
- **怎么用**：每个可能失败的外部调用都包一层「阶段 + 下一步」。

### 7）资源边界三件套：日志上限、TTL、流式

- **问题**：崩溃循环 + 无上限日志 + 无 TTL 转储 = 磁盘一夜被吃光。
- **做法**：容器日志 20m×2（`panel/server/src/docker.ts:780-782`）、日志 512KB/365 天（`panel/server/src/logs.ts:12-14`）、上传流式（`panel/server/src/upload.ts:1-7`）。
- **为什么好**：每个可写路径都有天花板，故障不会升级成灾难。
- **怎么用**：新功能评审时问一句「它的上限是什么」。

### 8）服务端凭据注入

- **问题**：上游（KasmVNC）需要 Basic 密码，但不能给浏览器。
- **做法**：凭据存服务端，反代时注入 `Authorization`（`panel/server/src/index.ts:1789-1795`）。
- **为什么好**：前端零秘密，XSS 也偷不到上游密码。
- **怎么用**：任何「前端 → 反代 → 有凭据的上游」架构。

### 9）按网络原点拒绝，而不是靠实例自觉

- **问题**：实例被攻破后能访问面板 API。
- **做法**：实例只接专用网络；面板拒绝来自该网段的请求（`panel/server/src/index.ts:149-155`）。
- **为什么好**：边界落在网络层，不依赖应用层自律。
- **怎么用**：管理面与控制面分网，管理面默认拒绝数据面来源。

### 10）发布门禁写成可执行命令

- **问题**：文档写「要测试」，没人执行。
- **做法**：`doc/dev/发布门禁.md` 全是可复制命令 + 期望输出（`doc/dev/发布门禁.md:28-67`）。
- **为什么好**：能贴结果、能追责、能进 CI。
- **怎么用**：把发布检查从 checklist 变成 shell script。

## 面试 Q&A（7 张）

**Q1：为什么用容器而不是 VM？**
A：目标用户是 NAS，资源有限；容器 + Xvfb + KasmVNC 足够跑微信，启动快、占用低。代价是共享内核、隔离弱——项目也明说容器不是安全边界（`doc/技术方案.md:23-29`）。

**Q2：多个用户怎么共享一个微信？**
A：不是多租户，是共享同一块远程桌面和同一个微信进程；面板只做访问控制。子账号只是「谁能进这个实例」，不是「每人一个微信」（`README.md:141`）。

**Q3：KasmVNC 凭据怎么保护？**
A：凭据只存服务端实例记录，API 返回 `publicInstance` 时剔除；反代请求时注入 Basic，浏览器永远拿不到（`panel/server/src/store.ts:50-51`、`panel/server/src/index.ts:1789-1795`）。

**Q4：KasmVNC 卡死怎么办？**
A：真实请求 25 秒无响应记一次 hang；10 分钟 2 次、运行满 3 分钟、15 分钟冷却外，自动 `keepImage` 重启实例；页面先回自动重连页（`panel/server/src/index.ts:1738-1773`）。

**Q5：升级面板和升级实例有什么区别？**
A：两个镜像、两个生命周期。面板自更新用 helper 容器重建自己；实例升级是拉新镜像重建容器、保留数据卷。恢复类操作绝不换镜像（`doc/dev/稳定性设计.md:52-84`）。

**Q6：最大的安全风险是什么？**
A：面板挂 `docker.sock` = 宿主 root。默认部署绝不能裸暴露公网；socket-proxy 也只是按端点过滤，仍可 create privileged 容器（`doc/安全加固.md:11-27`、`doc/安全加固.md:57-63`）。

**Q7：怎么保证不发布坏镜像？**
A：两道：本地发布门禁（DPI/CEF 连跑两次/崩溃循环/微信模式/KasmVNC 参数）+ CI 产物门禁跑在即将发布的 artifact 上。教训是「本地全绿不等于 CI 产物全绿」（`doc/dev/发布门禁.md:28-67`、`doc/dev/发布门禁.md:5-7`）。

## 可以吹的 5 个点

1. **单文件 2702 行的 docker 编排**，把创建/升级/备份/诊断/剪贴板全塞进一套生命周期。
2. **10 条架构守则全部从真实 P0 蒸馏**，每条都带「学费」和事故编号，比很多公司的 ADR 硬。
3. **CI 用原生 arm64 runner 替代 QEMU**，解决 apt OOM 导致的镜像发布失败（`.github/workflows/release.yml:6-9`）。
4. **单连接 viewer 设计**，同时规避 KasmVNC EncCache 泄漏和「两连接卡死 Xvnc」两个坑（`docker/Dockerfile:138-141`）。
5. **中文输入走「compositionend 整串发送 + 容器剪贴板」**，绕开 keysym 上限和逐字符丢字（`docker/Dockerfile:115-122`）。

## 不该抄的 5 个点

| 不该抄 | 原因 |
|---|---|
| 裸挂 `docker.sock` 的默认部署 | 面板被攻破=宿主 root；至少用 socket-proxy |
| `seccomp=unconfined` | 为兼容 Chromium 牺牲隔离；能用默认 profile 就别关 |
| 没有自动化测试 | 只靠发布门禁探针，回归靠人；新项目应补单测 |
| `bcrypt.compareSync` 同步校验 | 登录并发会阻塞事件循环；用异步 API |
| 2000+ 行的 `index.ts` / `docker.ts` | 可读性差；按域拆模块（proxy/lifecycle/auth）更好 |

## 一句话记住

WOC 最值得偷的不是某个函数，是**「把每次 P0 变成一条硬约束」的工程习惯**——代码会过时，约束不会。
